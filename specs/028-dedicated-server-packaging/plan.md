# Implementation Plan: Dedicated Server Packaging

**Branch**: `028-dedicated-server-packaging` | **Date**: 2025-12-18 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/028-dedicated-server-packaging/spec.md`

## Summary

Create Docker-based deployment infrastructure for plix-server with reproducible builds, runtime configuration, and documentation. The feature adds multi-stage Dockerfiles, docker-compose orchestration, bash deployment scripts, and comprehensive admin documentation while leveraging the existing CLI argument system for configuration.

**Key technical decisions**:
- Build on existing clap-based CLI args (no new config parsing library needed)
- Use debian:bookworm-slim as base image (good balance of size/compatibility)
- Pin Rust 1.75.0 via rust-toolchain.toml
- Default game port: UDP 7777 (not 12345 as spec assumed)
- Delegate log rotation to Docker/host tools

## Technical Context

**Language/Version**: Rust 1.75.0 (stable, pinned via rust-toolchain.toml)
**Primary Dependencies**: Docker 20.10+, docker-compose 2.0+, bash (existing Rust deps unchanged)
**Storage**: File-based (TOML config, binary world persistence via Feature 014)
**Testing**: Manual Docker build/run verification, cargo test for any new Rust code
**Target Platform**: Linux x86_64 (Docker containers), debian:bookworm-slim runtime
**Project Type**: Infrastructure/DevOps (no new Rust crates, config files and scripts only)
**Performance Goals**: Server starts within 30 seconds, image size <100MB
**Constraints**: Non-root container user, no external dependencies in runtime image
**Scale/Scope**: Single server deployment, optional multi-service stack with master

## Implementation Phases

### Phase 1: Version Pinning & Foundations

1. Create `rust-toolchain.toml` at repo root
2. Verify Cargo.lock is committed and used
3. Document base image choice (debian:bookworm-slim)

### Phase 2: Dockerfile (Server)

1. Create multi-stage `deploy/docker/Dockerfile`
2. Builder stage: Rust toolchain, compile release
3. Runtime stage: Minimal image, non-root user
4. Test local build and run

### Phase 3: Server Configuration

1. Add TOML config file support to plix-server
2. Implement config priority: CLI > ENV > file > defaults
3. Create example configuration file
4. Document all environment variables

### Phase 4: Data Directories

1. Define /data structure in container
2. Ensure server works without volumes (ephemeral)
3. Document volume mount points

### Phase 5: Docker Compose

1. Create docker-compose.yml with plix-server service
2. Add optional plix-master service (profile-based)
3. Configure networking, volumes, environment

### Phase 6: Deployment Scripts

1. Create build.sh for Docker image building
2. Create run.sh for simple container execution
3. Create compose.sh wrapper for docker-compose
4. Create release-local.sh for non-Docker archives

### Phase 7: Observability

1. Verify stdout/stderr logging
2. Document RUST_LOG usage
3. Add Docker HEALTHCHECK

### Phase 8: Documentation

1. Create DEDICATED_SERVER.md with full guide
2. Include deployment examples for all game modes
3. Add troubleshooting section

### Phase 9: Testing & Validation

1. Test docker build
2. Test docker run (default config)
3. Test docker run (custom config)
4. Test docker-compose (full stack)
5. Verify default FFA mode

### Phase 10: Polish

1. Verify existing tests pass
2. Verify cargo run still works
3. Clean up documentation
4. Final review
