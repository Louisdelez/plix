# Performance Report Schema

This document describes the JSON schema for performance reports generated by `plix-perf`.

## File Location

Reports are written to the path specified by `--output` (default: `perf_report.json`).

## Top-Level Structure

```json
{
  "metadata": { ... },
  "tick_stats": { ... },
  "subsystem_stats": { ... },
  "net_stats": { ... },
  "meshing_stats": { ... },
  "alloc_stats": { ... }
}
```

## Schema Reference

### metadata

Run configuration and environment information.

| Field | Type | Description |
|-------|------|-------------|
| `timestamp` | string | ISO 8601 timestamp of run start |
| `git_sha` | string | Git commit SHA (if available) |
| `build_mode` | string | `"release"` or `"debug"` |
| `scenario` | string | Scenario name: `"idle"`, `"world_churn"`, `"net_stress"` |
| `duration_secs` | number | Configured run duration in seconds |
| `tick_rate` | number | Target ticks per second |
| `player_count` | number | Simulated player count (net_stress only) |

**Example**:
```json
{
  "metadata": {
    "timestamp": "2025-12-19T10:30:00Z",
    "git_sha": "abc1234def5678",
    "build_mode": "release",
    "scenario": "idle",
    "duration_secs": 60,
    "tick_rate": 60,
    "player_count": null
  }
}
```

### tick_stats

Aggregate statistics for tick timing.

| Field | Type | Description |
|-------|------|-------------|
| `count` | number | Total ticks executed |
| `avg_ms` | number | Mean tick time in milliseconds |
| `p50_ms` | number | Median tick time |
| `p95_ms` | number | 95th percentile tick time |
| `p99_ms` | number | 99th percentile tick time |
| `max_ms` | number | Maximum tick time observed |
| `min_ms` | number | Minimum tick time observed |
| `overruns` | number | Ticks exceeding budget (>16.67ms) |

**Example**:
```json
{
  "tick_stats": {
    "count": 3600,
    "avg_ms": 8.5,
    "p50_ms": 7.2,
    "p95_ms": 12.1,
    "p99_ms": 15.8,
    "max_ms": 22.3,
    "min_ms": 0.8,
    "overruns": 5
  }
}
```

**Targets**:
| Metric | Good | Warning | Critical |
|--------|------|---------|----------|
| `avg_ms` | < 10 | 10-12 | > 12 |
| `p95_ms` | < 12 | 12-15 | > 15 |
| `p99_ms` | < 15 | 15-18 | > 18 |
| `overruns` | 0 | 1-10 | > 10 |

### subsystem_stats

Per-subsystem timing breakdown.

| Field | Type | Description |
|-------|------|-------------|
| `<subsystem_name>` | object | Stats for each tracked subsystem |
| `<subsystem>.avg_ms` | number | Mean time spent in subsystem |
| `<subsystem>.p50_ms` | number | Median time |
| `<subsystem>.p95_ms` | number | 95th percentile |
| `<subsystem>.p99_ms` | number | 99th percentile |
| `<subsystem>.max_ms` | number | Maximum time |

**Tracked subsystems**:
- `simulation`: Game logic, physics, AI
- `net_encode`: Network message serialization
- `meshing`: Chunk mesh generation
- `mods`: WASM mod execution
- `persistence`: World save operations

**Example**:
```json
{
  "subsystem_stats": {
    "simulation": {
      "avg_ms": 2.1,
      "p50_ms": 1.8,
      "p95_ms": 3.5,
      "p99_ms": 5.2,
      "max_ms": 8.1
    },
    "net_encode": {
      "avg_ms": 1.2,
      "p50_ms": 1.0,
      "p95_ms": 2.0,
      "p99_ms": 2.8,
      "max_ms": 4.5
    },
    "meshing": {
      "avg_ms": 3.2,
      "p50_ms": 2.5,
      "p95_ms": 6.0,
      "p99_ms": 8.5,
      "max_ms": 12.3
    }
  }
}
```

### net_stats

Network performance metrics.

| Field | Type | Description |
|-------|------|-------------|
| `messages_sent` | number | Total messages sent |
| `messages_received` | number | Total messages received |
| `bytes_sent` | number | Total bytes sent |
| `bytes_received` | number | Total bytes received |
| `bytes_per_sec` | number | Average bandwidth (bytes/sec) |
| `per_message_type` | object | Breakdown by message type |

**per_message_type fields**:
| Field | Type | Description |
|-------|------|-------------|
| `<type>.count` | number | Messages of this type |
| `<type>.total_bytes` | number | Total bytes for this type |
| `<type>.avg_bytes` | number | Average message size |

**Example**:
```json
{
  "net_stats": {
    "messages_sent": 45000,
    "messages_received": 12000,
    "bytes_sent": 2340000,
    "bytes_received": 156000,
    "bytes_per_sec": 39000,
    "per_message_type": {
      "position_update": {
        "count": 36000,
        "total_bytes": 1440000,
        "avg_bytes": 40
      },
      "chunk_data": {
        "count": 500,
        "total_bytes": 800000,
        "avg_bytes": 1600
      }
    }
  }
}
```

### meshing_stats

Chunk meshing performance metrics.

| Field | Type | Description |
|-------|------|-------------|
| `chunks_meshed` | number | Total chunks meshed |
| `mesh_time_avg_ms` | number | Average mesh generation time |
| `mesh_time_p95_ms` | number | 95th percentile mesh time |
| `vertices_generated` | number | Total vertices generated |
| `triangles_generated` | number | Total triangles generated |
| `cache_hits` | number | Mesh cache hits |
| `cache_misses` | number | Mesh cache misses |

**Example**:
```json
{
  "meshing_stats": {
    "chunks_meshed": 256,
    "mesh_time_avg_ms": 2.5,
    "mesh_time_p95_ms": 5.8,
    "vertices_generated": 1250000,
    "triangles_generated": 420000,
    "cache_hits": 180,
    "cache_misses": 76
  }
}
```

### alloc_stats

Memory allocation tracking (when enabled).

| Field | Type | Description |
|-------|------|-------------|
| `total_allocations` | number | Total allocation count |
| `total_bytes_allocated` | number | Total bytes allocated |
| `peak_memory_bytes` | number | Peak memory usage |
| `buffer_pool_hits` | number | Buffer pool cache hits |
| `buffer_pool_misses` | number | Buffer pool cache misses |

**Example**:
```json
{
  "alloc_stats": {
    "total_allocations": 125000,
    "total_bytes_allocated": 52428800,
    "peak_memory_bytes": 134217728,
    "buffer_pool_hits": 45000,
    "buffer_pool_misses": 2500
  }
}
```

## Parsing Reports

### Using jq

```bash
# Get p95 tick time
jq '.tick_stats.p95_ms' perf_report.json

# Find slowest subsystem
jq '.subsystem_stats | to_entries | max_by(.value.p95_ms)' perf_report.json

# Get network bandwidth in KB/s
jq '.net_stats.bytes_per_sec / 1024' perf_report.json
```

### Using Rust

```rust
use serde_json;
use plix_server::perf::PerfReport;

let json = std::fs::read_to_string("perf_report.json")?;
let report: PerfReport = serde_json::from_str(&json)?;

println!("p95: {}ms", report.tick_stats.p95_ms);
```

### Using Python

```python
import json

with open('perf_report.json') as f:
    report = json.load(f)

print(f"p95: {report['tick_stats']['p95_ms']}ms")
print(f"Overruns: {report['tick_stats']['overruns']}")
```

## Validation

Reports should be validated before comparison:

1. **Check build_mode**: Only compare `release` builds
2. **Check duration**: Longer runs (60s+) are more stable
3. **Check tick_count**: Verify expected count (duration * tick_rate)
4. **Check scenario**: Only compare same scenarios
